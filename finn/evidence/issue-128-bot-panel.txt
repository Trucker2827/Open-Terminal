## The gate section is absent, not zeroed

`kalshi-bot-gate.json` does not exist on this machine: the gate writer is ladder
rung 2 (PR #133), which is not merged. The panel therefore reads

    PAPER SCOREBOARD UNAVAILABLE · no kalshi-bot-gate.json — the promotion gate has not
    scored the paper record yet, so no settled count, P&L, or Brier is claimed
    GATE NOT EVALUATED · no kalshi-bot-gate.json

rather than showing a 0 settled / $0.00 P&L / 0.0000 Brier scoreboard — even
though a paper settlement DID land on this very tick (`settled 1 · realized
$0.35`). The panel does not score that itself; the gate does. The
PASS/FAIL-with-numbers rendering is covered by unit tests
(`gate_fail_renders_the_verdict_with_its_numbers`, `gate_pass_reads_pass`,
`unscoreable_brier_is_absent_not_zero`) against verdicts shaped exactly as
`KalshiBotGate::evaluate()` writes them; no gate file was hand-crafted to make
this screenshot look complete.

## Armed state

The ARMED line reads from the live session status the screen already polls
(`kalshi auto live status`, the session machinery of PRs #39/#44). This machine
has an armed Kalshi automation session, so the panel shows

    ARMED · shared Kalshi live session (the bot has no arm of its own) · caps in force:
    stake <= $2.00 · all-in <= $3.00 · <= 10 orders/hour · exposure $0.00 of $120.00

The line names whose arm it is, so an armed live session cannot be misread as an
armed bot — the bot is paper-only and has no arm until rung 5. The panel shows
DISARMED when the status reports no active session, and SESSION UNKNOWN / FAIL
CLOSED when the status cannot be read at all; it never renders an unreadable
status as disarmed.
